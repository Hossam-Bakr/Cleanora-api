# R1-P10 Migration Plan

Migration: `prisma/migrations/r1_p10_availability_capacity_textual_coverage/migration.sql`.

Add the Configuration and Providers tables described in data-model.md, relations from Country/Provider/Worker/User, check constraints, ordinary indexes and partial unique indexes. Add an optimistic-concurrency `version` column to `country_configs` before any statement that references it. Before altering `platform.default_timezone` to `COUNTRY_REQUIRED` (repair item 6), backfill a `country_configs` row for every active Country that lacks one, inheriting the existing global IANA value as its starting value at version 1; Egypt always ends with `Africa/Cairo`. The backfill never overwrites an existing per-country override (`NOT EXISTS` guard) and only then does the resolution policy switch. Existing global value remains for history. The backfilled row's id is a deterministic PostgreSQL-core expression (`'r1p10bf_' || md5(country_id || ':platform.default_timezone')`), not `gen_random_uuid()`, because no earlier migration declares the `pgcrypto` extension that function requires (final repair item 5); idempotency across reruns is still enforced by the `NOT EXISTS` guard, not by the id's determinism. `prisma/seed.ts` keeps its own idempotent Egypt upsert for clean setup, which is a no-op once the migration backfill has already run.

Add `configuration_locality_commands` (repair item 5): a Configuration-owned durable UUID-idempotency receipt table for Staff locality/time-zone writes, mirroring `provider_availability_commands`'s scope+key uniqueness, SHA-256 fingerprint check, `actorUserId` column and in-progress/accepted status-shape check. Owned entirely by Configuration; never referenced by Catalog or Providers. Both command tables' replay/reservation logic reserves via a transaction-safe `createMany({ skipDuplicates: true })` write and compares the stored `actorUserId` against the incoming actor on every replay decision, so a different actor presenting the same `(scopeKey, idempotencyKey)` is the same stable conflict as a changed payload (final repair items 3 and 4).

Add exact-duplicate-prevention unique indexes on `provider_schedules`/`worker_schedules` (provider/worker, weekday, start/end minute, endsNextDay) and partial unique indexes on `provider_schedule_exceptions`/`worker_schedule_exceptions` enforcing at most one holiday row per date and no duplicate open period per date (repair item 7). Overlap validation beyond exact duplicates stays application-level for Batch B.

SQL review must prove: no drop/truncate/reset, no applied-migration edit, all deletes restricted or append-only as designed, city/district and coverage uniqueness, coverage XOR, period/exception checks, capacity bounds, pause interval validity, one current pause, and that the backfill INSERT runs strictly before the `platform.default_timezone` resolution-policy switch. Upgrade proof records table digests before/after and verifies all Phase 9 Provider/service truth remains intact. Clean proof applies every migration chronologically, seeds twice and exercises constraints. Use only an explicitly phase-named disposable local/test database.
