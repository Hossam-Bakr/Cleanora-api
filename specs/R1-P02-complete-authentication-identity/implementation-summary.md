## Coverage-run database contention diagnosis and fix

### Proven root cause

Owner: **test harness + process-wide Prisma lifecycle pool ownership** (not weakened assertions; not mock replacement of PostgreSQL).

Evidence before the fix:

- Each failing file **alone** passed.
- The same four files **together** failed intermittently (pre-fix combined repeats: **1 fail / 2 pass** out of 3), with signup returning **500** (not 409).
- The coverage run also failed `worker-signup-rejection` with Prisma **`Unable to start a transaction in the given time`** (interactive-transaction `maxWait` exhaustion).
- `PrismaLifecycle` previously constructed `new PrismaPg({ connectionString })`, which creates an **internal pg Pool with default `max: 10` per lifecycle**. Every auth test creates/destroys a lifecycle. Vitest could still open **multiple worker processes**, so remote CI connections spiked under long/coverage runs.
- Signup 500s were unmapped infrastructure failures (not P2002 uniqueness). Transaction-start exhaustion must not be classified as `AUTH_SIGNUP_UNAVAILABLE`.

### Fix (smallest correct change)

| File | Change |
|---|---|
| `src/integrations/database/prisma-lifecycle.ts` | Explicit `pg.Pool` with `max: 2`, `allowExitOnIdle: true`, `PrismaPg(pool, { disposeExternalPool: true })`; warm `SELECT 1` after `$connect` so the first interactive transaction is not racing a cold SSL handshake under default `maxWait`. |
| `vitest.config.ts` | `maxWorkers: 1` + `fileParallelism: false` + `pool: "forks"` (Vitest 4 replacement for singleFork/`poolOptions`). |
| `tests/helpers/test-logger.ts` | Capture last safe error context for diagnosis. |
| `src/core/http/error.middleware.ts` | Log safe `causeName` / `causeCode` / fixed transaction-maxWait phrase only (no URLs, tokens, OTPs). |
| `tests/helpers/authentication/test-authentication-app.ts` | Expose logger; strengthen unique identity entropy. |
| `tests/helpers/authentication/worker-fixture.ts` | Align worker phone shape with Egypt `+201…` fixture pattern. |
| `tests/unit/integrations/prisma-lifecycle.test.ts` | Assert connect warms with one `$queryRaw`. |

No migration/schema edits. No assertion weakening. No timeout inflation of Prisma `maxWait`. No third full coverage run.
